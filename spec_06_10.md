# PART I — HALO REFRACTION LAYER

# 13. IDENTITY

**Public name:** Halo Refraction Layer  
**React export:** `HaloRefractionLayer`  
**Registry slug:** `halo-refraction-layer`  
**Category:** Foundations & Material

Purpose:

> Optional advanced optical layer that introduces restrained environmental distortion to selected HaloUI materials while preserving a stable fallback.

This is an advanced progressive-enhancement foundation.

It is NOT required for the core HaloUI material identity.

---

# 14. CORE PRINCIPLE

Refraction must follow this rule:

> The interface must remain complete when refraction is unavailable, disabled, reduced, unsupported, or too expensive for the current context.

Refraction is enhancement.

Never architecture.

---

# 15. WHAT REFRACTION REPRESENTS

Refraction conceptually represents subtle displacement of environmental information as light passes through or around a material.

HaloUI refraction should suggest:

- material thickness;
- optical curvature;
- environmental displacement;
- localized depth.

It must remain restrained.

---

# 16. WHAT REFRACTION MUST NOT BECOME

Do not turn Halo Refraction Layer into:

- watery distortion everywhere;
- jelly UI;
- wobbling glass;
- fisheye effects;
- lens distortion over text;
- continuously moving liquid animation;
- cursor-following gimmick;
- full-screen shader.

---

# 17. CONTENT SAFETY

Refraction must NEVER distort:

- text;
- icons;
- form values;
- focus indicators;
- interactive controls;
- accessibility-critical information.

Refraction affects the environmental/material layer.

Consumer content remains stable.

---

# 18. PUBLIC API

Keep the API extremely small.

Potential semantic model:

```ts
type HaloRefractionIntensity =
  | "subtle"
  | "balanced"
````

Potential:

```tsx
<HaloRefractionLayer intensity="subtle" />
```

Do not expose low-level shader/filter parameters.

---

# 19. DO NOT EXPOSE

Avoid APIs such as:

```tsx
<HaloRefractionLayer
  displacement={17}
  turbulence={0.42}
  frequency={0.018}
  scale={24}
  chromaticShift={3}
  distortionX={7}
  distortionY={4}
/>
```

Those are implementation details.

---

# 20. STRONG REFRACTION

Do not add `strong` merely to complete a three-option API.

If stronger distortion damages readability or becomes decorative spectacle, it does not belong in the public system.

---

# 21. IMPLEMENTATION STRATEGY

Investigate the least expensive implementation capable of producing the desired result.

Potential technologies may include:

* CSS;
* masks;
* gradients;
* localized transforms;
* carefully controlled SVG filters.

Do not choose WebGL simply because refraction sounds advanced.

Start with the cheapest reliable implementation.

---

# 22. SVG FILTERS

If SVG filters are considered:

test:

* browser support;
* repeated-instance performance;
* GPU/compositing cost;
* scaling;
* clipping;
* SSR;
* hydration;
* visual consistency.

Do not place unique expensive SVG filters in dozens of component instances without measuring impact.

---

# 23. WEBGL

Do not use WebGL for Halo Refraction Layer v1 unless there is a demonstrated requirement CSS/SVG cannot satisfy.

HaloUI is a component system, not a graphics engine.

---

# 24. FALLBACK

The fallback should effectively become:

**normal Halo Surface material without refraction.**

Do not show:

* broken effect;
* blank layer;
* warning;
* unsupported badge;

to end users.

Graceful fallback should be visually natural.

---

# 25. REDUCED MOTION

If refraction includes movement:

`prefers-reduced-motion` must simplify or disable that movement.

Static refraction may remain only if:

* it does not reduce readability;
* it does not cause discomfort;
* it remains useful.

Do not equate reduced motion with removing the entire component.

---

# 26. POINTER REACTION

Pointer-responsive refraction must NOT be default.

If later supported:

* localize it;
* avoid React rerenders;
* disable/simplify for reduced motion;
* make touch experience complete;
* maintain static fallback.

---

# 27. PERFORMANCE BUDGET

Refraction should be used on a small number of selected surfaces.

Do not recommend it for:

* every table row;
* every Input;
* every Button;
* every list item;
* dense repeated UI.

* Lift

---

# 51. PRESS

Used for short direct manipulation feedback.

Potential consumers:

* Button
* Icon Button
* interactive compact controls.

Motion should be:

* immediate;
* restrained;
* reversible.

---

# 52. LIFT

Used when a surface increases perceived elevation.

Potential consumers:

* interactive cards;
* floating controls;
* selected hover-capable surfaces.

Lift should not make UI jump significantly.

---

# 53. REVEAL

Used for entering content.

Potential consumers:

* Popover;
* Menu;
* Dialog content;
* expandable regions.

Reveal must preserve clear final state without motion.

---

# 54. SETTLE

Used after state/position transition.

It should communicate stabilization.

Avoid cartoonish bouncing.

---

# 55. FLOAT

Exceptional.

Potential consumers:

* selected showcase elements;
* Dock;
* floating material.

Do not use continuous floating motion throughout ordinary product UI.

---

# 56. TIMING MODEL

Align with HaloUI's motion principles:

* Micro: approximately 50–150ms
* State: approximately 100–220ms
* Reveal: approximately 200–500ms
* Navigation: approximately 250–600ms

These are design ranges.

Only expose exact public token values that exist in code.

* press;
* opacity;
* transform;
* reveal.

* easing;
* distance;
* scale;
* spring-like behavior where implemented.

Reduced motion should simplify/disable:

* parallax;
* magnetic behavior;
* floating;
* large transforms;
* kinetic typography;
* Dock magnification;
* moving refraction.

Preserve:

* state;
* selection;
* focus;
* progress;
* loading;
* expanded/collapsed understanding.
