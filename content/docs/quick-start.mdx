# Quick start

Install a HaloUI component, render it in your application, and verify your setup.

This guide assumes your React project is already configured for the HaloUI registry workflow. If you still need to configure your project, complete the [Installation](/docs/installation) guide first.

## Before you begin

Make sure your project satisfies the following prerequisites:

- **React 19+** project using Next.js (App Router) or Vite
- **Tailwind CSS v4** configured in your styling pipeline
- **shadcn/ui initialized** with a valid `components.json`
- **Access to the HaloUI registry** (`https://haloui.dev/r/registry.json`)
- **A supported package manager** (`pnpm`, `npm`, `yarn`, or `bun`)

The steps below focus strictly on adding and using your first component.

## Install a component

Begin with Button, a small component that makes it easy to verify your HaloUI setup.

<InstallCommand registry="button" />

The CLI installs the component source and resolves the dependencies declared by its registry item.

The generated files now belong to your application.

## Import the component

Import Button from the location generated by your registry configuration:

<CodeBlock
  language="tsx"
  filename="app/page.tsx"
  code={`import { HaloButton } from "@/components/ui/halo-button"`}
/>

Your import path may differ if your `components.json` aliases use a different component destination (for example, `@/components/haloui/button`).

## Render the component

Add the component to a page or another React component:

<CodeBlock
  language="tsx"
  filename="app/page.tsx"
  showLineNumbers
  code={`import { HaloButton } from "@/components/ui/halo-button"

export default function Page() {
  return (
    <main className="flex min-h-screen items-center justify-center p-6">
      <HaloButton>Continue</HaloButton>
    </main>
  )
}`}
/>

<QuickStartButtonPreview />

The surrounding preview uses the neutral documentation interface. The Button itself uses HaloUI's liquid-material system.

HaloUI components are Client Components when they require interaction physics, but the wrapping page or layout can remain a Server Component unless it uses client hooks.

## Run your application

Start your local development server:

<InstallCommand action="dev" />

Open your application in the browser and confirm that the component renders.

## Verify the result

Your first HaloUI component is working when:

- `HaloButton` imports without TypeScript or bundling errors.
- HaloUI styling is visible (optical boundary, translucent tint, specular reflection).
- Pointer hover responds with illumination, and clicking compresses the button with tactile physics.
- Keyboard navigation (<kbd>Tab</kbd>) displays a visible optical focus ring.
- The component responds correctly to the application's light and dark theme changes.

<Callout type="tip">
  HaloUI is ready. Additional components can now be installed through the same registry workflow.
</Callout>

## Customize the component

Because the installed component is part of your source tree, you can adapt its implementation when your product requires behavior or styling beyond the public API.

<Callout type="note">
  Prefer HaloUI tokens and existing variants for normal customization before changing foundational material behavior.
</Callout>

For system-wide material changes, use the [Theming](/docs/theming) guide rather than editing the same values independently across components.

## Check light and dark themes

Verify the component against the themes supported by your application.

HaloUI's material layers maintain readable content, visible boundaries, and appropriate hierarchy across supported themes.

Because translucent surfaces respond to their surroundings, evaluate material components against both neutral and contextual backgrounds. A HaloUI surface placed on a completely uniform background may intentionally appear more restrained.

## Common mistakes

### Importing from the wrong path

Use the destination generated by your registry configuration rather than assuming every HaloUI project uses the same alias. Check your `components.json` aliases if an import cannot be resolved.

### Installing before shadcn/ui is configured

If the registry command cannot resolve the project correctly, complete the [Installation](/docs/installation) guide and verify that `components.json` is initialized first.

### Missing global material styles

Confirm that the global HaloUI styles and tokens (`styles/halo-tokens.css`) required by the installed registry item are included by your application's global stylesheet.

### Adding "use client" unnecessarily

Do not convert a page or layout to a Client Component merely because it renders a HaloUI component. Add `"use client"` only when the consuming file itself uses client-side React features such as state, effects, or browser APIs.
