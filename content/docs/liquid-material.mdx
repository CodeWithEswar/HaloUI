# Liquid Material

HaloUI uses a shared CSS material for controls, navigation and floating context above the content layer. Articles, tables, documentation and large static containers should remain neutral and opaque.

The design takes inspiration from the functional hierarchy and concentric geometry described in Apple's [Meet Liquid Glass](https://developer.apple.com/videos/play/wwdc2025/219/) and [Materials guidance](https://developer.apple.com/design/human-interface-guidelines/materials). This is an original web approximation, not Apple's native compositor. It does not sample background pixels or automatically select a contrasting foreground.

## Material lab

Compare the actual production recipes across six environments. Use the stage viewport controls and keyboard to inspect focus, disabled, invalid and pressed states. Clear requires a controlled background: it is intentionally not the default for forms or menus.

## Recipes and intensity

| Recipe | Purpose | Behavior |
| --- | --- | --- |
| Regular | Controls, navigation, floating context | Balanced transmission and readable tint |
| Clear | Controlled imagery with independently verified contrast | Increased environmental transmission |
| Prominent | An important action or elevated control group | Stronger tint and hierarchy |

Intensity controls reflection strength, independently of recipe and elevation. Subtle suits dense controls; Balanced is the default; Rich is exceptional. Rich is not better. Density selects diffusion: compact 12px, regular 14px, floating 16px, overlay 22px.

```tsx
import { HaloSurface } from "@/components/ui/halo-surface"

export function FloatingControls() {
  return (
    <HaloSurface material="regular" intensity="balanced" elevation="floating">
      <nav aria-label="Workspace">Workspace controls</nav>
    </HaloSurface>
  )
}
```

## Optical foundations

| Foundation | Responsibility |
| --- | --- |
| Surface | Transmission, tint, diffusion, saturation and brightness |
| Edge | Masked directional perimeter, strongest toward a shared 135-degree light source |
| Highlight | Restrained reflection near the upper-left light position |
| Refraction | Optional static perimeter approximation; no pixel displacement |
| Noise | Optional microscopic static texture, not visible grain |
| Glow | Explicit exceptional emphasis; never focus, selection or default elevation |
| Focus Ring | Independent keyboard indication |
| Motion | Shared press, lift, reveal and settle vocabulary |
| Background | Deterministic reference environments |
| Scrim | Modal background attenuation, not glass |
| Portal Surface | Floating material; existing optional portal creation remains supported |

The shared renderer composes the body, edge and reflection with a root and two pseudo-elements. Isolated negative stacking keeps optics behind bare text as well as wrapped content. Refraction does not introduce a second backdrop filter or distort content. Static CSS rendering does not need a pointer listener or animation loop.

## Elevation and geometry

Inset uses an inner contact shadow. Base uses a tight contact shadow. Raised, Floating and Overlay add increasing ambient separation. Elevation does not make a surface arbitrarily opaque; choose Prominent when stronger tint is necessary.

Semantic radii are control-sm (10px), control (14px), control-lg (18px), floating (22px), and overlay (26px). Derive a nested control radius from its parent's radius minus the inset. Avoid layering another blurred surface inside a floating material.

## Virtual lighting and interaction

Edge and reflection use a shared 135-degree direction with light positioned at 35% horizontally and 12% vertically. Compact actions lift on hover and compress slightly on press. Text-entry fields do not lift. Focus uses a dedicated ring, never the optical edge. The canonical renderer supports directional virtual lighting with pointer-responsive specular tracking via `--halo-pointer-x` and `--halo-pointer-y`.

## Theme adaptation

The existing next-themes architecture remains the theme authority. Light and dark environments have separate body, reflection, edge, brightness and shadow values. Scoped preview themes reset these tokens locally. A theme determines tint; it does not guarantee contrast over arbitrary photography.

## Transparency and motion preferences

Place the explicit preference on the application root when portals should share it, or on a subtree for local previews. A portal mounted outside a locally scoped preference needs that preference on its container too.

```tsx
<div data-transparency="reduced" data-motion="reduced">
  <HaloSurface>Solid material with reduced motion</HaloSurface>
</div>
```

The material also responds to prefers-reduced-transparency where supported and prefers-reduced-motion. Reduced transparency replaces the body with an opaque theme color and removes backdrop filtering. Increased contrast uses solid surfaces and visible boundaries. Forced colors uses system colors. Browser support for the transparency media query varies, so the explicit attribute is always available.

## Accessibility

Retain semantic labels, native or primitive keyboard behavior, visible focus and validation states. Test selected with focus, invalid with focus, and open with focus. Material is not evidence of WCAG compliance. Measure text and icon contrast against the actual rendered background; use Prominent, an opaque surface, or a controlled background when needed. Disabled content must remain understandable even when muted.

## Tokens and source ownership

Import styles/halo-tokens.css once from the application's global stylesheet. It imports styles/halo-material.css. Registry items include both files. Existing material class names remain compatibility entry points to the same renderer.

| Token group | Examples |
| --- | --- |
| Body | --halo-material-body, --halo-material-alpha, --halo-material-solid |
| Lighting | --halo-material-light, --halo-material-soft, --halo-material-opposite, --halo-material-reflection |
| Diffusion | --halo-material-brightness; semantic density selects blur and saturation |
| Elevation | --halo-material-contact, --halo-material-ambient |
| Geometry | --halo-radius-control, --halo-radius-floating, --halo-radius-overlay |
| Shared light | --halo-light-angle, --halo-light-x, --halo-light-y |

Private variables prefixed with --_halo are recipe implementation details. Components should consume recipes rather than exposing raw blur, edge opacity or refraction strength as public props.

## Performance and browser fallback

Use one backdrop filter per material root. Avoid nested filters, per-item filters in menus and tables, full-screen moving blur, global pointer listeners and per-frame React updates. The refraction approximation adds no shader, SVG displacement filter or rendering dependency. Noise uses a static texture only when explicitly requested.

Without backdrop-filter support the body is solid. Without mask-composite support the perimeter uses a simple border. This fallback is intentional; no claim of identical rendering across browsers is made.

## Usage guidelines

| Use | Avoid |
| --- | --- |
| Glass on functional controls and navigation | Glass articles, tables or every card |
| Regular for ordinary floating surfaces | Clear everywhere |
| Independent focus and selected indicators | Glow or highlights as the only state |
| One material surface around a control group | Glass inside glass with nested filters |
| Controlled backgrounds with measured contrast | Transparent forms over arbitrary photography |
| Restrained static perimeter approximation | Refraction over text or distorted labels |
| Shared recipes and geometry | Component-specific blur and competing inset shadows |

## Migration

HaloSurface adds material and density without removing existing intensity/elevation props or elevation aliases. Existing .halo-liquid-glass and .halo-liquid-glass-surface consumers receive the shared engine. Surface's noise, refraction and specular options now affect rendering. Portal Surface no longer duplicates Edge and Highlight layers. Component-specific visual styles require a separate audit; changing the common engine alone does not certify every component.
